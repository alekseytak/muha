# RFC-001 · Проект III «Анаклеарный Рой» — ризома без центра

- Статус: DRAFT v1.0 · Домены: memory / atqec / hardware
- Источники вдохновения: Ж. Делез/Ф. Гваттари (ризома), П. Энтони
  («Кластер», перенос ауры), анаклеарные нейроны дрозофилы
  («АРФА-анализ коннектома дрозофилы_.pdf»), М. Хайдеггер (Dasein)

## 1. Мотивация

Анаклеарные нейроны мухи функционируют БЕЗ клеточных ядер — доказательство
того, что «центр» не обязателен для функции. Рой строится по тому же
принципу: нет королевы, нет центрального координатора; каждый агент —
оболочка, в которую можно перенести «ауру» (политику + опыт + веса)
любого выпускника-Учителя. Потеря узла не разрушает сеть (ризомный
принцип разрыва).

## 2. Архитектура

```
     ┌────────┐   gossip    ┌────────┐   gossip    ┌────────┐
     │ fly-01 │◀───────────▶│ fly-02 │◀───────────▶│ fly-03 │
     │ aura:  │             │ aura:  │             │ aura:  │
     │ Scout  │             │ Guard  │             │ Scout  │
     └───┬────┘             └────────┘             └───┬────┘
         │                                             │
         │ pheromone traces (картография, не копия)    │
         ▼                                             ▼
   ┌────────────────────────────────────────────────────────┐
   │            общее феромонное поле + OmegaRegistry        │
   │        (единственная «вертикаль» — только Registrar)    │
   └────────────────────────────────────────────────────────┘

   Перенос ауры:  Teacher(fly-01) ──serialize+sign──▶ Shell(fly-09)
                  capability(ученика) ⊆ capability(учителя)
```

## 4. АРФА на сенсорном входе (код владельца, «Код на фильтры.txt»)

Каскад: csc_filter (хронон-чувствительность, температура мозга 310.15K)
→ harp_filter (TDA, 4 уровня разрешения, числа Бетти)
→ royal_mole_filter (8 кубитов, октавы, декогеренция 1e-6 с)
→ apfa_filter (Рамануджан-гармоники + ограничения Ферма p ≡ 1 mod 4).

Проверено владельцем на коннектоме дрозофилы: 100% каналов
классифицированы как «Гений», P_transition 0.512–0.514, σ = 0.000007.

## 5. Аура: контракт

```yaml
aura:
  identity: fly-01-teacher
  capability_set: [R, WL, X, E]        # НЕ включает WR
  policy_version: os-glagolov/1.0
  weights_digest: sha256:...           # дайджест синаптических весов
  golden_apples: [hash1, hash2]        # ссылки на канон Registry
  hormone_profile: {...}               # снимок настроения
  signature: sha256:...                # подпись Registrar
```

Правила переноса (НЕ ТРОГАТЬ):
- capability ученика ⊆ capability учителя;
- WR не передаётся НИКОГДА (Charter п.6);
- аура без подписи Registrar не принимается;
- перенос — это verb-act Registrar'а «версирует» (L5).

## 6. Метрики приёмки

- рой решает задачу после удаления 30% узлов (деградация ≤ 20%);
- gossip-консенсус сходится за ≤ 10 раундов на 32 узлах;
- перенесённая аура воспроизводит поведение учителя с agreement ≥ 0.85;
- каскад АРФА улучшает SNR сенсорного входа (эталон владельца: +49.6%).

## 7. Риски

- дрейф ауры при многократных переносах → дайджест весов + подпись;
- раскол роя (византийские соседи) → вето Guardian + кворум 2/3;
- феромонное загрязнение → TTL и затухание поля.
