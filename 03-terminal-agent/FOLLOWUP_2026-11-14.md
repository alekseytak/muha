## Состояние до новых исправлений

Последние пользовательские изменения прошли штатный набор 143/143. Однако три новые сквозные регрессии упали по существу:

- `test_content_action_words_are_written_verbatim`: запрос «Запиши в result.txt текст прочитай и запусти» дал read вместо write.
- `test_fallback_cannot_overwrite_when_append_was_requested`: ошибочное WRITE от fallback перезаписало существующий файл вместо неподдерживаемого append.
- `test_fallback_cannot_ignore_do_not_save`: ошибочное WRITE от fallback создало файл вопреки «не сохраняй».

Все действия были в временной песочнице, модель заменена фиксированным ответом. Настоящие учётные данные и платные API не использовались.

## Минимальные изменения

1. `core/micromodels.py`: при выборе правила слова после явного маркера содержимого CONTENT_RE исключаются из инструкции. Поэтому текст записи больше не становится read/execute.
2. `core/readiness.py`: существующий intent_guard теперь включает NEGATION_STEM_RE. Это закрывает разрыв между fast-path и проверкой перед исполнением fallback.
3. `core/agent.py`: WRITE отклоняется, если исходный запрос требует дописывания или parameters.mode=append. Инструмент append не поддерживает, поэтому fallback тоже не может молча перезаписать файл.
4. `eval/compare_gold.py`: подписи исправлены. Скрипт измеряет предложения fast-path, а не реальные исполнения. Ноль в его dangerous-счётчике не означает безопасность всего агента. Модельные метки не изменялись.

## Что намеренно не сделано

- Append не добавлен. Безопасный отказ лучше неподтверждённой операции записи.
- В G043 конечный `?` может быть пунктуацией вопроса или частью URL. Не удаляем вслепую символ адреса ради совпадения с моделью.
- В G063 воздержание вместо recommend оставлено. Текущий ui.recommend строится по состоянию агента, а не даёт предметный совет про запись файла. Совпадение имени глагола не сделало бы ответ полезным.
- Никаких заявлений об универсальном понимании отрицаний. Guard эвристический, безопасность за пределами проверенных случаев не доказана.
- gold_proposals.tsv не стал человеческим gold. Пустой gold_candidates.tsv не заполнялся от имени человека. Человеческую проверку можно отложить, она нужна для claims о независимом качестве, но не блокирует исправление конкретных воспроизводимых ошибок.
