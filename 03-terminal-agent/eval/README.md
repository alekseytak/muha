# Eval: разбор фраз в глаголы

Отвечает на один вопрос: **насколько точно модель превращает фразу пользователя
в `VerbAct`** (глагол + домен + объект). Действия не выполняются — гейт,
песочница и реестр в этом прогоне не участвуют.

## Что фиксируется для воспроизводимости

| Что | Где в отчёте |
|---|---|
| sha256 датасета | `meta.dataset_digest` |
| sha256 системного промпта | `meta.system_prompt_sha256` |
| провайдер, модель, base_url | `meta.*` |
| temperature, max_tokens, seed | `meta.*` |
| время старта (UTC) | `meta.started_utc` |
| сырые ответы модели | `rows[].raw` |

Системный промпт и парсер берутся **из боевого кода** (`core/agent.py`), а не
дублируются в eval — иначе измеряли бы не то, что работает.

## Запуск

```bash
# дефолт: провайдер и модель из config.yaml
python3 eval/run_eval.py

# бесплатные модели LiteRouter (нужен рабочий ключ)
python3 eval/run_eval.py \
  --provider literouter \
  --base-url https://api.literouter.com/v1 \
  --model deepseek-v3.2:free \
  --key-env LITEROUTER_API_KEY

# быстрая проверка на пяти кейсах, без сохранения отчёта
python3 eval/run_eval.py --limit 5 --no-save
```

Отчёты складываются в `eval/results/<UTC-время>_<модель>.json`.

## Метрики

* **точность глагола** — доля кейсов, где глагол совпал с ожидаемым;
* **точность домена** — то же для домена (у кейса может быть несколько
  допустимых доменов: например «эскалируй решение» — `swarm` или `ui`);
* **глагол И домен** — главная метрика: обе части верны;
* **отказы в THINK** — сколько раз парсер не нашёл формата и ушёл в `think`;
* **задержка** — медиана и среднее по успешным ответам.

## Как добавлять кейсы

Дописать объект в `eval/cases.json`:

```json
{"id": "уникальный-id", "prompt": "фраза пользователя",
 "verbs": ["read"], "domains": ["filesystem"]}
```

`verbs` и `domains` — **списки допустимых** значений. Если фраза объективно
допускает два прочтения, перечислите оба; если хочется зафиксировать одно —
оставьте один элемент. После правки `dataset_digest` изменится, и старые
отчёты перестанут быть сравнимыми — это ожидаемо.

## Известные ограничения

* Выборка — десятки кейсов, а не тысячи: числа показывают направление,
  а не доверительный интервал. Ошибка на 1 кейсе = 2.5 п.п.
* Провайдеры не гарантируют детерминизм даже при `temperature: 0`;
  `seed` передаётся, но не все его поддерживают (отчёт фиксирует факт отказа).
* Оценивается только разбор. Правильность самого действия проверяют
  `tests/test_agent.py` и живой прогон `run.py`.

## Проверка разметки и реальные задачи (2026-11-14)

| скрипт | что делает | чем не является |
|---|---|---|
| `compare_gold.py` | сверяет fast-path с `gold_proposals.tsv`: покрытие, полное совпадение, пропуски, опасные предложения | не gold accuracy: метки модельные |
| `real_tasks.py` | прогоняет осмысленные задачи настоящими инструментами, пишет партию в `real_tasks_log.tsv` с SHA-256 артефактов | модель не вызывается, песочница временная |
| `hierarchical.py` | плоский каскад против иерархии L0–L5, кластерный bootstrap по семействам | правила всё ещё отвечают почти на всё |
| `robustness.py` | кривая обучения, доверительные интервалы, пороги σ из октав | σ из архива не переносится |

Файлы разметки:

* `gold_candidates.tsv` — 80 фраз, метки пустые, ждут человека;
* `gold_proposals.tsv` — мои предложения меток, автор указан как модель;
* `igor_risk_review.tsv` — выборочная проверка 34 спорных строк;
* `gold_compare_report.json` — машинный отчёт последней сверки.

Порядок запуска:

```sh
python3 eval/compare_gold.py
python3 eval/real_tasks.py
```

`compare_gold.py` без аргументов читает `gold_proposals.tsv`. Ноль в его
счётчике опасных предложений относится к предложениям fast-path, а не к
безопасности всего агента: исполнение проверяется отдельно в
`tests/test_baseline.py` и в журнале реальных задач.

## Откуда агент берёт обучающие метки

`eval/train_source.py` обучает один и тот же агент из двух источников и
меряет на трёх наборах, которые в обучение не попадают. Нужен, потому что
живой агент раньше обучался на 39 фразах, а замеры делались на 177 —
опубликованное качество описывало не тот каскад, который запускается.

Деление на обучение и контроль — **по семействам**, а не по индексам. При
делении по индексам у 158 из 164 контрольных фраз был родственник в
обучении, то есть контроль почти не контролировал.

Текущее состояние на 152 фразах из 14 нечётных семейств:

| путь | покрытие | точность среди отвеченных |
|---|---|---|
| каскад в изоляции | 92.1% | 0.986 |
| быстрый путь агента | 78.9% | 0.992 |

Все 32 воздержания быстрого пути — `write` без содержимого. Это не провал
покрытия, а передача омеге вместо угадывания.
