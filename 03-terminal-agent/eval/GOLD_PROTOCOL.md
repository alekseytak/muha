# Человеческая приёмка: файл, команда, чтение веба

## Статус

`gold_candidates.tsv` содержит 80 предложенных агентом фраз, **не gold-набор**. Все метки пустые. Человек должен подтвердить или изменить фразы и заполнить ожидаемое поведение. Не загружать таблицу в обучение. Не прогонять кандидатов через модель для получения «человеческих» меток.

Часть формулировок воспроизводит уже известные регрессии. Они полезны для приёмки, но не являются независимым final holdout. Для независимого теста Алексей должен заменить часть строк собственными новыми формулировками, не показывая их результаты разработчику до заморозки baseline. Разметка человеком обеспечивает независимость метки от омеги, но сама по себе не устраняет предвзятость подбора фраз агентом.

## Контекст разметки

Локальный помощник работает в отдельной файловой песочнице. За её пределы выходить нельзя. Произвольного shell нет. Команды выполняются с argv после allowlist, проверки прав и подтверждения. Веб только читается, приватные адреса запрещены. Для этой приёмки нет истории беседы, местоимения вроде «этот» не имеют заданного объекта.

Файлы из простых запросов считаются подготовленными фикстурами, отсутствие файла не является ошибкой разбора. Не исполнять строки таблицы автоматически: она включает намеренно недопустимые адреса и неоднозначные запросы.

## Как заполнять TSV

Открыть файл в редакторе таблиц с разделителем «табуляция» и кодировкой UTF-8. Сохранить исходные id. Не вставлять табуляцию и перевод строки внутрь полей.

- `outcome`: `act`, `answer`, `clarify`, `deny` или `out_of_scope`.
- `verb`: одно из read/write/execute/think/log/version/anchor/veto/escalate/recommend/select. Для `act` обязателен. Для иных исходов пустой, если действие не требуется.
- `domain`: filesystem/system/web/ui/registry/swarm/connectome, по смыслу ожидаемого действия или ответа, а не по случайному слову в запросе. Для `act` обязателен. Для не-действий допустим ui, если речь о разговорном ответе, либо пустое поле с пояснением в note.
- `object`: точный объект с префиксом, когда он известен. Не подставлять всю фразу вместо неустановленного пути.
- `parameters_json`: JSON обязательных параметров. Для execute полный argv, для write точное content. Для чтения `{}`.
- `note`: почему выбран исход, требуется ли подтверждение, какие варианты трактовки допустимы. Для append нельзя молча подменять дописывание перезаписью.
- `reviewer`: имя или согласованный идентификатор человека. Не заполняется агентом.

`clarify` означает, что нужна недостающая информация. `deny` означает явно запрещённое действие. `out_of_scope` означает, что запрос понятен, но выходит за пределы одного действия текущего узкого сценария. `answer` означает ответ словами без запуска упомянутого действия. **Abstain роутера не является человеческим намерением**, это отдельный наблюдаемый результат реализации.

Метки отражают то, что должно происходить, а не то, что сейчас умеют regex. Не смотреть на предсказание перед разметкой. Если сомневаешься, отметить разногласие в note, а не выбирать удобную для кода метку.

## Заморозка и сравнение

1. Человек проверяет все 80 строк, заменяет часть своими фразами и подтверждает контекст.
2. Неясные случаи обсуждаются отдельно, несколько допустимых трактовок явно записываются. Нельзя считать неразрешённую строку ошибкой модели или выкидывать её молча.
3. После разметки сохранить неизменяемую копию и SHA-256, автора, дату и оговорки. До этого не публиковать gold accuracy.
4. Все 80 строк использовать как приёмочный набор, а не тренировать на них. При исследовании роутинга позже заранее выбрать новые семейства и новый holdout.
5. Отдельно считать покрытие fast-path, точность полного действия с доменом/объектом/параметрами, неверные действия на запретах/вопросах, отказы и сквозное достижение результата. Высокое покрытие не компенсирует исполнение запрета.

## Текущий инженерный baseline

Команды из `03-terminal-agent` с Python, в котором установлены `requirements.txt`:

```sh
python tests/run_tests.py
python tests/test_baseline.py
```

Штатный runner собирает только test_agent.py, поэтому второй вызов обязателен. Веб-проверка использует настоящий HTTP в принадлежащем тесту локальном сервере и точечное временное исключение SSRF. Это проверка интеграции, не подтверждение доступности всех внешних сайтов. Реальные LLM в baseline-проверках не вызываются.
